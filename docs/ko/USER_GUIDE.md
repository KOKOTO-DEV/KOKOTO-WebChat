# KOKOTO WebChat 5.3.1 — 사용자 가이드

반응 authority, 직결/다단 전달, 원문 서버 단절 outbox, 작성자 알림 그림은 [REACTIONS.md](REACTIONS.md)를 참고하세요.

이 문서는 일반 사용자를 위한 핵심 사용법입니다. 서버 설치·운영은 `INSTALLATION_OPERATIONS.md`, 구현 세부사항은 `TECHNICAL_REFERENCE.md`, 전체 장문 참고서는 `USER_MANUAL.md`를 보세요.

## 공개 채팅
![공개 메시지 처리 흐름](../assets/public-message-flow.svg)

일반 채팅 화면에서 게임 ↔ 웹 대화를 사용합니다. 답글, 고정, 검색, 업로드, 커스텀 이모지, 미리보기, 최신 메시지 이동이 같은 타임라인에서 동작합니다. 이름 클릭 동작과 메시지 본문 reply 동작은 분리되어 URL은 기존 링크 동작을 유지합니다.

## 계정과 게스트
연동된 Minecraft 계정은 서버 사용자 신원을 유지하며 지원되는 채팅/알림 설정을 계정 단위로 동기화할 수 있습니다. 게스트는 관리자가 허용한 경우에만 사용할 수 있고 이름, CAPTCHA, 세션, moderation 정책을 적용받습니다.

## DM과 그룹 채팅

![비공개 Reply 검증 및 서버간 식별 흐름](../assets/private-reply-flow.svg)

![DM/그룹 메시지·읽음·typing·relay 흐름](../assets/private-conversation-flow.svg)

[PNG](../assets/private-reply-flow.png) · [SVG](../assets/private-reply-flow.svg)

1:1 DM은 수신자 UI 또는 `/kchat dm`, 그룹 room은 그룹 UI 또는 `/kchat group`으로 사용합니다. 게임에서는 DM/그룹 대화 이름을 클릭하면 해당 명령이 준비되고, 비공개 메시지 본문을 클릭하면 reply가 준비됩니다. 실제 전송 시 서버가 DM 참여 여부/현재 그룹 멤버십을 다시 확인합니다.

**Standalone 데스크톱 모드**에서 화면 작업영역이 **900 × 480 이상**이면 메시지함/그룹 목록을 부모 창으로 유지한 채 각 DM 또는 그룹방을 별도 자식 창으로 열 수 있습니다. 같은 대화는 중복 창을 만들지 않고 기존 창을 앞으로 가져옵니다. 각 창은 제목 드래그 이동, 바깥쪽 투명 8방향 크기 조절, 제목 더블클릭 최대화/복원을 지원하며 기존 **닫기** 버튼으로 개별 종료합니다. 부모 메시지함/그룹 목록을 닫으면 그 부모에서 열린 자식 대화창과 종속 팝업도 함께 닫힙니다. 900 × 480 미만에서는 멀티윈도우를 사용하지 않고 기존 단일 목록→대화 화면으로 동작합니다. 맵 어댑터 임베드 화면은 지원되는 멀티윈도우 배포 모드로 문서화하지 않습니다.


로그인 사용자는 공개채팅, DM, 일반 그룹채팅 메시지에 Unicode 또는 KWC 커스텀 이모지 반응을 추가할 수 있습니다. 그룹 입장/퇴장 이벤트 행에는 반응을 달 수 없습니다. 실제 반응이 없을 때 `+` 버튼은 32 × 16px이며 현재 본문 아래와 다음 메시지 앞에 각각 1px의 시각적 여유를 두어 어느 쪽 글도 덮지 않습니다. 반응 기능을 끄면 빈 요소를 만들지 않아 기존 8px 메시지 간격을 그대로 사용하고, 실제 반응이 생기면 정상 in-flow 반응 행/칩 간격으로 전환합니다. 선택창은 이모지 문자 자체, 서버가 생성한 Unicode 이름, 관리자가 편집한 검색 별칭, 커스텀 이모지 ID/이름/팩으로 검색할 수 있습니다. 별칭은 **관리자 > 이모지 > 반응 아이콘**에서 `이모지 = 검색어` 형식으로 편집하며 `reaction-search-aliases.txt`에 저장됩니다. 검색 별칭은 반응 picker 검색에만 사용하며 공개채팅/DM/그룹채팅 입력을 변환하지 않습니다. 카테고리를 바꿔도 처음 열린 화면 위치를 유지하고 재렌더 후에도 바깥 빈 곳을 누르면 닫힙니다. 반응 hover에서는 반응자 이름 전체를 최대 4줄 높이의 스크롤 목록으로 확인할 수 있으며, 이름은 일반 채팅 송신자와 같은 표시이름 ↔ 원래이름 전환을 사용합니다. 관리는 해당 관리자 화면에서만 제공하며 picker에는 관리 버튼을 넣지 않습니다. 전체 ON/OFF와 KWC 커스텀 이모지 허용은 다른 관리자 설정과 같은 둥근 테마 행을 사용합니다. 기능을 끄면 기존 저장 기록은 보존·표시하되 읽기 전용으로 두고, 추가와 제거를 포함한 모든 로컬/Relay 반응 변경을 막습니다. 공개/DM/그룹의 `입력 중...`은 5초 동안만 보이는 임시 상태입니다. 서버 관리자가 Web Admin **Settings** 또는 `chat.typing-indicator.*`에서 오픈채팅/DM/그룹채팅을 각각 제어하며 기본값은 OFF/ON/ON입니다. `chat.typing-indicator.user-display-control`의 기본값은 OFF입니다. 관리자가 이를 켜면 로그인 사용자의 채팅 설정에 계정 저장형 **입력 중 표시** 하나가 나타납니다. 사용자가 끄면 서버에서 허용된 범위의 다른 사용자 typing 표시만 본인 화면에서 숨기며, 본인의 입력 중 상태 전송은 계속됩니다. 메시지 기록에 저장되지 않고 본인의 typing은 본인에게 표시되지 않습니다. 둥근 표시가 입력창 위에 플로팅되고 일반 채팅의 표시이름 ↔ 원래이름 전환을 따르며 이름의 formatting tag를 제거합니다. 글꼴은 사용자 채팅 글꼴의 약 80%를 사용하되 기본 UI 글꼴보다 작아지지 않습니다. 그룹에서 여러 긴 이름이 한 줄에 들어가지 않으면 자동으로 입력 중인 인원수로 축약합니다.

![저장된 대화 생명주기](../assets/archive-lifecycle.svg)

DM/그룹 방에서는 **설정**에서 권한이 있을 때 초대, **대화 저장**, 저장된 대화, 숨기기, 방 관리 기능을 사용합니다. 대화 저장 UI는 서버의 `chat.conversation-archive.enabled: true`(기본값)일 때만 생성되며, 끄면 관련 DOM과 archive API가 모두 비활성화됩니다. 실제 방 관리 항목은 해당 관리 권한이 있는 사용자에게만 보이고 나가기는 제목창에 그대로 있습니다. 대화 저장은 첫 메시지와 끝 메시지를 선택해 개인 snapshot을 만듭니다. 다만 관리자 삭제/잠금 정책이 항상 우선합니다. PDF는 현재 KWC 화면 설정을 사용하고 원본이 남아 있는 이미지만 포함하며 다른 파일은 링크로 남기고 원본이 없으면 유실로 표시합니다.

최신 메시지 자동추종 판정은 공개/DM/그룹 모두 현재 실제로 렌더링되는 line-height를 사용합니다. 최하단까지 남은 간격이 글자 **2줄 미만**일 때만 최신 메시지를 따라가며, 그보다 위를 보고 있으면 새 메시지나 레이아웃 변화만으로 최하단으로 끌어내리지 않습니다. 이모지/아이콘/첨부 패널을 열고 닫아도 현재 viewport를 보존하고, 새로고침/재연결 후에도 가능한 경우 저장된 원래 대화 위치를 복원합니다.

## 답글·이모지·미디어
답글은 원문 전체를 보존합니다. 등록된 커스텀 이모지는 reply preview에서도 표시되고 중첩 링크는 만들지 않습니다. 이모지 선택기는 caret 위치에 정확한 token만 삽입하며 자동 공백을 붙이지 않습니다. newline alias로 만든 연속 이모지 전용 줄은 간격을 줄이고 의도적인 빈 줄은 그대로 유지합니다.

## 알림과 화면 설정
데스크톱 알림, Web Push, 키워드 설정, 계정 UI profile, 테마/폰트/text-shadow, PIP는 서버가 제공하는 웹 설정에서 조정합니다. 창 위치/크기와 Push endpoint 같은 device-local 상태는 각 기기에 남지만, 비공개 대화의 '보고 있음' 판정은 계정 전체에 적용됩니다. 같은 계정으로 로그인된 KWC 화면 중 하나라도 실제로 보이고 포커스된 상태이며 채팅창이 최소화되지 않았고, DM/그룹창이 열려 있으며 현재 스레드/방 ID가 새 메시지 대상과 정확히 일치하면 해당 대화를 보고 있는 것으로 판정합니다. 그 화면 자체에 Web Push 구독이 없어도 되며, 이 동안에는 같은 계정의 모든 연결된 KWC 탭에서 해당 DM/그룹의 브라우저 알림과 브라우저 로컬 알림함 추가를 억제하고 모든 기기의 Web Push도 억제합니다. 다른 방·닫힌 창·숨김/비활성 탭·최소화 상태라면 보고 있지 않은 것으로 처리되어 정상 알림이 다시 옵니다.

## 문제가 있을 때
서버 업데이트 후 먼저 웹 페이지를 새로고침하고 현재 접속 URL과 로그인 상태를 확인하세요. 관리자는 데이터 파일을 직접 수정하기 전에 설치·운영 가이드와 Wiki의 `Troubleshooting`을 확인하는 것을 권장합니다.
