BlueMapWebChat 4.6.2 final release validation

Release basis
- All changelog and upgrade documentation describes the final 4.6.2 delta from the published 4.6.1 source baseline.
- Development-time 4.6.2 intermediate behavior is not listed as a release change.

Final status UI
- Normal successful delivery has no delivery label.
- Pending delivery uses compact localized text beside the timestamp:
  en-US: Sending
  ko-KR: 전송중
  ja-JP: 送信中
  zh-CN: 发送中
- Failed delivery uses compact localized text/action beside the timestamp:
  en-US: Failed / Retry
  ko-KR: 실패 / 재시도
  ja-JP: 失敗 / 再試行
  zh-CN: 失败 / 重试
- 1:1 DM unread state is not numeric. It uses a short localized word:
  en-US: Unread
  ko-KR: 미확인
  ja-JP: 未読
  zh-CN: 未读
- A 1:1 DM changes from the unread word to ✓ when its recipient has read that message.
- Group-chat receipt rendering is unchanged from the previous 4.6.2 source: unread recipients remain a numeric count and 0 unread recipients renders ✓.
- Read status is calculated for every DM/group message rather than being gated by the current viewer being the sender.

Delivery/read reliability retained
- Unqualified DM names resolve only on the current server; cross-server targets require explicit server-scoped identity.
- Cross-server DM remains pending internally until the destination server confirms storage.
- HTTP/routing/timeout/destination failures remain retryable failures.
- Retry reuses persistent relay IDs; browser retries reuse client message IDs to prevent duplicate stored messages.
- Cross-server DM read acknowledgements are authenticated, idempotent, replayable, and forwarded through hub/chain topologies.
- Multi-hop delivery succeeds upstream only after the final destination confirms storage.

Update notification reliability
- The Modrinth release parser regression harness selects listed release 4.6.2 over listed release 4.6.1 while ignoring a beta candidate.
- Version comparison regression verifies 4.6.2 > 4.6.1.
- Eligible login notice checks explicitly accept OP or bluemapwebchat.update.notify.
- Eligible administrator login schedules a rate-limited asynchronous refresh instead of only consuming the periodic cached result.
- Modrinth HTTP, parsing, DNS/TLS, and other request failures are surfaced as WARNING logs with duplicate-warning throttling.
- Closing/reloading an UpdateChecker unregisters its listener.

Runtime/static validation performed
- inner.js passes node --check.
- src/main/resources/web/chat.js passes node --check.
- BMWC_EMBEDDED_INNER_TEXT decodes exactly to inner.js.
- Extracted renderer execution test passes:
  - delivered 1:1 unread -> Unread (not numeric 1)
  - delivered 1:1 read -> ✓
  - delivered group unreadMemberCount=3 -> 3
  - delivered group unreadMemberCount=0 -> ✓
  - pending -> Sending
  - failed -> Failed + Retry
- The group receipt branch is byte-for-byte identical to the preceding 4.6.2 unread-count source.
